# Informe adversarial de 1.0.0

hekit 1.0.0 copia la compuerta de release de Cthulhu Git y la deja solo en Linux. La suite del producto es `cargo test --locked`, que incluye `tests/adversarial.rs`. Los hallazgos F salen de leer los workflows, igual que en Cthulhu Git 0.0.2. No se copian los tests de producto de aquel repositorio: atacan un cliente de Git, no este protocolo HID.

## Heredados y mantenidos

| Id | Severidad | Estado | Qué queda |
| -- | --------- | ------ | --------- |
| F4 | Media | Arreglado en el workflow | `inputs.label` entra una sola vez como variable de entorno `LABEL`. Los `run:` usan `"$LABEL"`. |
| F5 | Media | Arreglado en el workflow | Las actions están clavadas al commit que Cthulhu Git usaba el 2026-10-01, no a un tag móvil. `softprops/action-gh-release` publica solo en el job que tiene `contents: write`. |

## Aceptados

| Id | Severidad | Por qué se queda |
| -- | --------- | ---------------- |
| F1, F2 | Alta, residual | Clavar las actions de publicación quita el intercambio de un tag móvil. Quien puede empujar un tag `v*` todavía publica el workflow de ese commit. La comprobación de "tiene que estar en `main`" vive en el commit etiquetado, así que no es una compuerta independiente. La protección del tag corresponde al repositorio de GitHub, no a este workflow. |
| F3 | Alta en Cthulhu Git | Allá, `cargo test` solo corría en Ubuntu y se añadió Windows y macOS. hekit es solo Linux a propósito: CI y release corren en `ubuntu-24.04`. No es un hueco que este release vaya a cerrar. |
| F6 | Media | El `.deb` se instala en CI. El `.rpm` se inspecciona con `rpm -qpi`, `rpm -qpR` y `rpm -qpl`. El AppImage se extrae y su binario corre `hekit --check`. No hay una prueba de la ventana. |
| F7 | Media | `action-gh-release` actualiza un release que ya existe y sobrescribe los archivos. Empujar el mismo tag otra vez vuelve a publicar. La guía dice que un tag publicado no se mueve; el arreglo siguiente es un patch. |

## Comprobado

`tests/adversarial.rs` cubre las tramas, los topes de eje, la capa Fn, los pares SOCD, el JSON y los comandos que no deben enviarse. `actionlint` 1.7.12 y `zizmor --persona auditor` forman parte de CI y del job de verificación del release. El `.deb` no usa `--multiarch`, para que la regla siga en `/usr/lib/udev/rules.d/70-hekit.rules`.
